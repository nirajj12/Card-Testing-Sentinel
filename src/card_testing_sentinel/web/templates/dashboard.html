How a request is decided

The current processor outcome is never available to the current decision.

  1. 01Receive request

    Accept a strict raw pre-authorization event.

  2. 02Build signals

    Use only previously committed lifecycle events.

  3. 03Score and apply policy

    Run the frozen model and deterministic rules.

  4. 04Return action

    Allow, review or block this request.

  5. 05Update state

    Record later outcomes for future decisions.
